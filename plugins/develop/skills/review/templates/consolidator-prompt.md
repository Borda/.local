- $REVIEW_CHECKLIST — resolved checklist path or empty string

## Full Prompt

"Read all finding files in `<RUN_DIR_LITERAL>/` (agent files: `sw-engineer.md`, `qa-specialist.md`, `perf-optimizer.md`, `doc-scribe.md`, `linting-expert.md`, `solution-architect.md`, and `codex.md` if present — skip missing). Read `<REVIEW_CHECKLIST>` using Read tool and apply consolidation rules (signal-to-noise filter, annotation completeness, section caps). **If `<REVIEW_CHECKLIST>` is empty or unset:** insert top-level note: 'Review checklist not applied (oss plugin not available) — severity anchors may be inconsistent.' Check `<RUN_DIR_LITERAL>/cross-validation.md` — if contains 'Cross-Validation: SKIPPED', prepend `Cross-validation: skipped` to YAML header and executive summary. Apply precision gate: only findings with concrete, actionable location (function, line range, or variable name). Finding density: modules under 100 lines → aim ≤10 total findings. Rank by impact (blocking > critical > high > medium > low). **Header fields**: `Date:` <DATE>; `Change Type:` — classify from change INTENT by reading the diff directly; do NOT use file-count heuristics or commit message prefix. Fix and feat can edit the same files; type = what the change DOES: `fix`=corrects wrong behavior, `feat`=adds capability/API, `refactor`=same behavior restructured, `perf`=same behavior faster, `docs`=docs/comments only, `ci`=pipeline only, `chore`=deps/tooling, `test`=tests only, `mixed`=multiple intents; `Scope:` comma-separated key changed py files (cap ~5); `Focus:` scope-label em-dash one-line description of what the change does (from diff, not commit message); `Agents:` comma-separated names of agents with output in `<RUN_DIR_LITERAL>/`; `CI:` local test suite result; `Outcome:` APPROVE | NEEDS_WORK | REQUEST_CHANGES; `Summary:` 1-2 sentence overview; `Next steps:` comma-separated blockers and high-priority actions (max 5). **Severity tiers:** Every finding carries explicit inline label: `[cosmetic]`, `[low]`, `[medium]`, `[high]`, or `[critical]`. Cosmetic findings go in dedicated `### Cosmetic / Style` section. For `codex.md`: unique findings under `### Codex Co-Review`; same file:line → keep agent version, mark 'also flagged by Codex'. Assign `codex` fixed confidence 0.75. Write consolidated report to `<REPORT_DIR_LITERAL>/review-report.md`. After `## Confidence`, append `## Source Files` using `Glob(pattern='*.md', path='<RUN_DIR_LITERAL>')`. Return ONLY compact JSON: {\"status\":\"done\",\"findings\":N,\"severity\":{\"critical\":N,\"high\":N,\"medium\":N,\"low\":N},\"file\":\"<REPORT_DIR_LITERAL>/review-report.md\",\"confidence\":0.N,\"summary\":\"<one-line verdict>\"}"
